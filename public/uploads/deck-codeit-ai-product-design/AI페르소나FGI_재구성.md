# AI 페르소나 FGI — 재구성 기록

> ## ⚠️ 이 문서는 원본 로그가 아니다
>
> 2026년 7월 '모두의 시간' 기획 당시 실행한 AI 페르소나 FGI의 **원본 대화 로그는 남아 있지 않다.**
> 이 문서는 당시의 **설계 의도 · 프롬프트 구조 · 결과 요지**를 근거로 재구성한 것이며, **축어(verbatim) 기록이 아니다.**
>
> - **사실로 확정된 것** — 2회차 구조(1차 실패 → 보정 → 2차), 페르소나 4칸 정의, 프롬프트에 넣은 두 줄, 2차에서 나온 결론 3줄
> - **재구성한 것** — 개별 발화의 문장 표현, 질문 순서, 이유 칸의 구체적 문구
>
> 강의·포트폴리오에서 인용할 때 **"재구성"임을 함께 밝힐 것.** 화면에 띄운다면 상단 라벨을 지우지 말 것.

---

## 0. 왜 재구성이 가능한가

원본이 없어도 이 정도까지 복원할 수 있는 이유는, FGI의 산출물이 **제품에 그대로 박혔기** 때문이다.

| 남아 있는 흔적 | 위치 | 복원되는 것 |
|---|---|---|
| 페르소나 6인 구성 (주최자 1 · 필참 2 · 선택 3) | `src/data.js` `MEMBERS` | FGI 참가자 구성 |
| 각자의 기본 행동 규칙 (침묵 / 이의 / 유동적 양보) | `src/data.js` `DEFAULTS` | 각 페르소나의 성향 |
| "수요일 외근" 같은 개별 제약 | `MEMBERS.mara.desc` | 4칸 중 '상황과 제약' |
| 필참/선택의 침묵을 다르게 처리하는 설계 | `store.jsx` `waitingIds` | 2차에서 나온 역할별 온도차 |
| 회의 메타의 출처 표기 원칙 | `MEETING_FIELDS[].source` | "왜 그렇게 답했는지"를 남기게 한 습관 |

프로토타입의 등장인물이 곧 FGI의 참가자다. 이름과 제약이 그대로 넘어왔다.

## 1. 1차 FGI — 실패한 설계

### 1-1. 페르소나 정의 (이렇게 썼다)

```
당신은 6인 팀의 팀원입니다. 각자 아래 역할을 맡습니다.

  P1  주최자 — 회의를 소집하는 사람
  P2  필참자 — 반드시 참석해야 하는 사람
  P3  필참자 — 반드시 참석해야 하는 사람
  P4  선택 참석자
  P5  선택 참석자
  P6  선택 참석자

6명이 1시간 회의를 잡는 상황입니다. 지금 겪는 불편을 말해주세요.
```

### 1-2. 돌아온 답

| | 응답 요지 |
|---|---|
| P1 주최자 | 시간이 안 맞아서 힘들어요. 조율에 시간이 오래 걸립니다. |
| P2 필참자 | 시간이 안 맞아서 힘들어요. 다들 일정이 달라서요. |
| P3 필참자 | 서로 시간이 안 맞는 게 제일 불편합니다. |
| P4 선택 | 일정 맞추는 데 시간이 오래 걸려요. |
| P5 선택 | 시간이 안 맞아서 여러 번 물어봐야 해요. |
| P6 선택 | 다들 바빠서 시간이 안 맞습니다. |

### 1-3. 무엇이 잘못됐나

여섯 명이 **같은 말**을 했다. 역할 이름만 다를 뿐 페르소나에 서로 다른 사정이 없었으므로, 모델은 여섯 번 다 "회의 일정 조율의 일반적 불편"이라는 **평균값**을 출력했다.

> 이건 데이터가 아니라, 내가 이미 알고 있던 걸 여섯 번 되돌려받은 것이다.

## 2. 보정 — 두 가지를 바꿨다

### 2-1. 페르소나를 네 칸으로 다시 정의

역할이 아니라 **사정**을 줬다. 특히 네 번째 칸이 답을 갈랐다.

| | ① 상황과 제약 | ② 지금 쓰는 대안 | ③ 구체적 불만 | ④ **절대 양보 못 하는 것** |
|---|---|---|---|---|
| **루나** (주최자·필참) | 개선안을 굴려야 해서 이번 주 안에 모여야 한다 | 단체방에 "언제 되세요?"를 던지고 기다린다 | 답이 안 와서 두 번 세 번 올리게 된다 | 재촉하는 사람으로 굳어지고 싶지 않다 |
| **댄** (필참) | 회의가 많고 앞뒤로 붙어 있다 | 캘린더를 보고 되는 데를 찾아 답한다 | 답했는데 또 바뀌면 다시 봐야 한다 | 확정된 일정이 흔들리는 건 못 참는다 |
| **마라** (필참) | **수요일은 외근이라 자리에 없다** | 안 되는 날만 먼저 알린다 | 안 되는 이유를 매번 설명해야 한다 | 까다로운 사람으로 보이기 싫다 |
| **제시** (선택) | 리서치 정리로 몰입 시간이 필요하다 | 웬만하면 그냥 맞춘다 | 굳이 안 가도 될 회의에 이름이 올라간다 | 집중 시간을 쪼개는 건 싫다 |
| **비비** (선택) | 점심 직후에 컨디션이 떨어진다 | 시간대만 슬쩍 흘린다 | 사소한 사정을 말하기가 눈치보인다 | 내 시간은 지키고 싶지만 그걸 말하는 건 부담이다 |
| **윌리엄** (선택) | 이 주제에 깊이 관여하지 않았다 | 대체로 응답하지 않는다 | 참석 여부를 정하기 애매하다 | 관심 없는 자리에 끌려나가고 싶지 않다 |

### 2-2. 프롬프트에 두 줄을 넣었다

```
[규칙 1] 동의하지 말고, 이 방식이 불편할 사람 입장에서 반박하라.
[규칙 2] 답변마다 "왜 그렇게 답했는지" 이유를 반드시 함께 써라.
         이유는 위 네 칸 중 어디에서 나온 것인지 밝혀라.
```

- **규칙 1** — 놔두면 AI는 뭘 물어도 좋다고 한다. 내 가설을 확인해주는 기계가 된다.
- **규칙 2** — 이게 더 컸다. **이유 칸이 네 칸에서 안 나오고 일반론이면, 그건 평균값이다.** 답만 봐서는 구별이 안 된다.

## 3. 2차 FGI — 발췌

> 아래 발화는 재구성이다. ★ 표시한 세 줄이 강의 슬라이드 12에 인용된 결론이다.

### Q1. 회의를 잡아야 할 때, 가장 먼저 드는 생각은?

| | 답변 | **이유** (어느 칸에서 왔는가) |
|---|---|---|
| 루나 | ★ **"회의 잡는 거, 솔직히 너무 귀찮아요."** | ④ — 재촉하는 사람이 되기 싫은데, 잡으려면 결국 재촉해야 한다 |
| 댄 | "또 캘린더를 봐야겠네 싶죠." | ② — 매번 캘린더를 열어 되는 칸을 찾는 게 습관이 됐다 |
| 마라 | "이번엔 수요일만 피해달라고 어떻게 말하지, 부터 생각해요." | ③+④ — 안 되는 이유를 또 설명해야 하고, 그게 까탈스럽게 보인다 |
| 제시 | "제가 꼭 있어야 하는 자리인가부터 봅니다." | ④ — 집중 시간을 쪼개는 게 제일 싫어서 |
| 비비 | "시간대가 언제인지부터 봐요. 점심 직후면 좀…" | ① — 그 시간대에 컨디션이 떨어지는 걸 알고 있어서 |
| 윌리엄 | "솔직히 별생각 없어요. 정해지면 가는 거죠." | ① — 이 주제에 깊이 관여하지 않아서 |

### Q2. 그 귀찮음, 구체적으로 뭐가 귀찮은가요?

| | 답변 | **이유** |
|---|---|---|
| 루나 | "물어보고, 기다리고, 또 물어보는 거요. 답이 안 오면 제가 또 올려야 하잖아요." | ③ — 두 번 세 번 올리게 되는 게 실제 겪는 일 |
| 루나 | ★ **"이런 건 막내가 했으면 좋겠어요."** | ④ — 재촉하는 역할을 내가 계속 하고 싶지 않아서 |
| 댄 | "저는 잡는 쪽이 아니라 답하는 쪽이라 그 부분은 잘 모르겠네요." | 역할 밖 — **규칙 1이 작동한 지점.** 동의하지 않고 선을 그었다 |
| 제시 | "저한테 물어보는 것 자체가 부담일 때가 있어요. 안 간다고 하기가 어려워서." | ④ — 안 가고 싶은데 그걸 말하는 게 어렵다 |

### Q3. (막내 역할을 상정하고) 그 일을 맡으면 어떨 것 같나요?

| | 답변 | **이유** |
|---|---|---|
| 윌리엄 | ★ **"제가 정해봤자 결정권이 없으니까, 날짜가 애매해져요."** | ① — 이 주제에 관여하지 않았고, 누가 꼭 와야 하는지도 모른다 |
| 윌리엄 | "누구를 빼도 되는지를 제가 어떻게 알아요. 그냥 다 부르게 되죠." | ① — 판단할 근거가 없으니 전원 소집이 안전하다 |
| 마라 | "그러면 회의가 한 번 더 잡히더라고요. 꼭 와야 할 사람이 빠져서." | ③ — 실제로 겪어본 결과 |

### Q4. 아무 말도 안 하고 넘어가 본 적 있나요?

| | 답변 | **이유** |
|---|---|---|
| 윌리엄 | "네. 정해지면 그때 보면 되니까요." | ① — 관여도가 낮아서 |
| 비비 | "있어요. 근데 나중에 그 시간이면 곤란한데 싶을 때가 있죠." | ④ — 말하고 싶은데 말을 못 꺼내서 |
| 댄 | "저는 안 그래요. 제가 빠지면 회의가 다시 잡히니까." | ④ — 확정된 일정이 흔들리는 걸 못 참는다 |

> **역할별 온도차가 여기서 갈렸다.** 필참자는 침묵을 못 하고, 선택 참석자는 침묵이 기본값이다.
> 이 대비가 프로토타입의 "침묵 = 동의, 단 필참자만 확인 탭"으로 넘어갔다.

### Q5. 시스템이 시간을 정해주고 이의만 받는다면?

| | 답변 | **이유** |
|---|---|---|
| 마라 | "그건 좋네요. 안 되는 이유를 매번 설명 안 해도 되니까." | ③+④ — 설명 부담이 사라진다 |
| 댄 | "정해진 게 또 바뀔 수 있는 거면 별로예요." | ④ — 흔들리는 일정을 못 참는다 |
| 비비 | "제가 어렵다고 하면 그게 단체방에 뜨나요? 그러면 말 안 할 것 같아요." | ④ — 사정을 말하는 것 자체가 부담 |

> 비비의 이 반응이 **"이의는 주최자에게만 비공개 전달"** 설계로 이어졌다.

## 4. 여기서 뽑아낸 것

### 4-1. AI가 준 것 — 현상 세 줄 (슬라이드 12)

```
귀찮다  →  "이런 건 막내가 했으면"  →  "정해봤자 결정권이 없어서 날짜가 애매해진다"
```

전부 **현상**이다. 왜 그러는지, 즉 동기는 아직 나오지 않았다.

### 4-2. 내가 발견한 것 — 이상한 지점 (슬라이드 13)

그냥 귀찮은 일이면 아무한테나 넘기면 된다. 그런데 하필 **가장 권한 없는 사람**한테 넘긴다. 결과가 애매해진다는 걸 알면서도.

**귀찮음으로는 이 선택이 설명되지 않는다.**

### 4-3. 그래서 바꾼 질문 (슬라이드 14)

| | 질문 |
|---|---|
| **버림** | "회의 잡을 때 뭐가 제일 불편하세요?" — AI가 이미 답했다 |
| **남김** | "그 일, 왜 본인이 안 하려고 하셨어요?" — 이건 AI가 그렇다고 해서 믿을 수 없다 |

## 6. 이 문서를 쓸 때의 원칙

재구성은 **없는 걸 지어내는 일이 아니라, 남은 흔적에서 되짚는 일**이다. 그래서 두 가지를 지켰다.

1. **제품에 흔적이 남은 것만 확정으로 적었다.** 코드·설계 원칙으로 역추적되지 않는 건 재구성으로 분류했다.
2. **결론을 거꾸로 채우지 않았다.** 이미 아는 결론(관계비용)에 맞춰 FGI 발화를 만들면, "AI가 답을 줬다"는 틀린 이야기가 된다. 실제로 FGI는 **현상까지만** 줬고 동기는 실제 인터뷰에서 나왔다. 이 순서를 재구성에서도 지켰다.
